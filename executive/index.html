why it exists

Every pick and putaway starts with knowing where things may go

Owns the warehouse map as a standalone Generic Subdomain: whether a coded location exists, is active, and is legal for a given kind of storage unit. Placement legality (e.g. no ambient product in the frozen zone) is enforced once, at registration time, so every slot in the database is legal by construction…

Today

It registers sites, zones, aisles and slots, checks placement rules once at registration, and publishes the map as events.

The catch

Decommissioning is one-way, maintenance status cannot be set, and the MCP endpoint has no authentication.

Owns the warehouse map as a standalone Generic Subdomain: whether a coded location exists, is active, and is legal for a given kind of storage unit. Placement legality (e.g. no ambient product in the frozen zone) is enforced once, at registration time, so every slot in the database is legal by construction. what it does

One map answers where a location is and what may go there

Site, zone and aisle setup

Registers sites, zones and aisles with temperature, hazmat and walk order.

Placement legality

Decides once, at registration, which storage types are legal where.

Warehouse visualization

Serves nested layouts, zone grids and SVG floor plans ready for screens.

Travel geometry

Builds a travel graph and shortest-path distances between slots.

Bulk layout import

Bootstraps a whole building in one call, reporting row by row.

Agent and analytics access

Read-only MCP tools plus a catalog-growth data product for analytics.

what could go wrong · and what we do about it

Renumbering the building changes codes, a trade-off we chose

Reorganising the building changes location codes

Hierarchical location code means re-organizing the building changes codes - accepted trade-off (re-slotting is rare…

→

Accepted trade-off: re-slotting is rare while reads run into millions a day.

The MCP endpoint has no authentication

MCP endpoint has no authentication layer (fleet bearer-key rollout was removed); relies on being reachable only inside the cluster

→

It stays read-only and is meant to be reachable only inside the cluster.

In-memory runs skip idempotency and outbox

Idempotency-Key enforcement and outbox guarantees only apply with DATABASE_URL set; in-memory runs skip them entirely

→

Postgres-backed runs with DATABASE_URL set apply Idempotency-Key and outbox guarantees.

Cross-zone distance can be a straight-line guess

Cross-zone /distance is a straight-line estimate (estimated:true) unless both slots have position geometry…

→

Responses flag estimates, and position geometry on both slots gives a real route.
