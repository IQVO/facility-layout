strategy

Mission & Role in the Fleet

Owns the warehouse map as a standalone Generic Subdomain: whether a coded location exists, is active, and is legal for a given kind of storage unit. Placement legality (e.g. no ambient product in the frozen zone) is enforced once, at registration time, so every slot in the database is legal by construction. As an Open Host Service with a Published Language (12 domain events plus REST) and zero inbound dependencies, it lets the WMS and WES tiers depend on the map without depending on each other.

What This Delivers

Structural hierarchy management

Site, Zone, Aisle registration with temperature class, hazmat flag and walk-order sequence hints

Placement-rule legality

Deny/Allow rules keyed by zone predicate decide which LocationTypes are legal where, at registration time

Warehouse visualization

pre-ordered nested layout, 2D zone grid and server-side SVG floor plan for direct UI rendering

Travel geometry

aisle centrelines, cross-aisles, fixed structures and a metre-weighted travel graph with shortest-path /distance

Bulk layout import

one call bootstraps a whole building with atomic-per-row partial-success reporting

Agent and analytics surface

read-only MCP tools plus a Layout Catalog Growth data product on a dedicated analytics topic

risk register

Risks & Watchouts

Hierarchical location code means re-organizing the building changes codes - accepted trade-off (re-slotting is rare; reads are millions/day)

MCP endpoint has no authentication layer (fleet bearer-key rollout was removed); relies on being reachable only inside the cluster

Idempotency-Key enforcement and outbox guarantees only apply with DATABASE_URL set; in-memory runs skip them entirely

Cross-zone /distance is a straight-line estimate (estimated:true) unless both slots have position geometry, else 422 no-route-between-zones
