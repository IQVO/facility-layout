The READ-ONLY analytical surface of the facility-layout "Layout Catalog Growth & Change" data product, served by the separate `cmd/facility-reports` binary over a read-only pool (`default_transaction_read_only=on`) against the analytical database — NOT by the OLTP `cmd/facility` binary documented in apis/openapi.yaml.
The report is a projection over this service's own domain events (SiteRegistered, ZoneRegistered, AisleRegistered, LocationTypeRegistered, PlacementRuleDefined, LocationSlotRegistered, LocationSlotDecommissioned, FacilityLayoutImported), delivered on the `warehouse.facility.analytics` topic and applied by `cmd/facility-projector`, the single writer. It is therefore EVENTUALLY CONSISTENT: use GET /reports/catalog-growth/freshness to see how far behind the event stream the read model currently is.
The layout is a slow-changing reference catalog, so rows are bucketed by UTC DAY, not by hour.
